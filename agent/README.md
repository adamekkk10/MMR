# RMM Agent

Transparent endpoint agent for the RMM server. Installs as a visible system service
(`rmm-agent.service` on Linux, `RMM Agent` on Windows) with a clear name and,
once the tray subsystem lands, a visible tray icon on user sessions.

## Design principles

- **Transparent by default.** No hidden processes, no innocuous names.
- **Outbound-only.** The agent initiates a WebSocket connection to the server. No
  inbound ports required on the endpoint.
- **Signed enrollment.** First contact uses a short-lived enrollment token minted
  in the panel. The server returns a long-lived agent token (later replaced by
  mTLS certs).
- **Auditable.** Every remote action the server asks the agent to run is logged
  server-side *before* execution and acknowledged by the agent with a result.

## Install config

Installers are generated by the server with a pre-baked `install_config.json`:

```json
{
  "server_url": "https://rmm.example.com",
  "enrollment_token": "rmmenr_xxxxxxxxxxxxxxxxxxxxxxxx",
  "verify_tls": true,
  "tags": ["homelab", "linux"]
}
```

Place it at `/var/lib/rmm-agent/install_config.json` (Linux) or
`%PROGRAMDATA%\RMM Agent\install_config.json` (Windows), then run the agent once
to enroll:

```
python -m rmm_agent --once-enroll
```

On success the server returns a permanent `agent_token`, written to `agent.json`
with `0600` permissions (Linux). The `install_config.json` file can be deleted
after enrollment; only the `verify_tls` flag is read from it on subsequent runs.

## Running

```
pip install -r requirements.txt
python -m rmm_agent
```

In production this runs under systemd / a Windows service. PyInstaller builds
for Windows/Linux are produced by the server's installer-generator endpoint
(coming in a later milestone).

## What the agent sends

- On connect: `hello` with OS, version, arch, hostname, primary IP, MAC addresses.
- Every 15s (configurable per-server): `heartbeat` with CPU%, memory%, disk%,
  load average, uptime.
- In response to server commands: `result` messages. (Command execution is
  stubbed for the MVP; see `client._on_message`.)

## What the agent does NOT do

- No phone-home to any third party.
- No telemetry outside your own server.
- No silent install, no hidden service, no anti-tamper tricks.
